- parquet/model_ready

- logs/
- backups/

Недочеты для полной реализации Stage Two:
1. Parquet layer был описан слишком общо.
2. Не были выделены branch/role/modality partitions.
3. Не были выделены schemas/ и config/ для schema contracts, parser registry seed и label mapping rules.
4. reports/ не был разделен на parser/normalization/quality/leakage/schema_mismatch.
5. DuckDB layer не содержал sql/ и exports/.
6. Не был явно описан принцип: raw datasets остаются вне изменения и могут храниться в PATH_FOLDER_DATASETS / PATH_FOLDER_DATASETS_FILTER.
7. Не был зафиксирован принцип относительных путей для artifacts.

3. НАЗНАЧЕНИЕ ДИРЕКТОРИЙ
================================================================================

postgres/
- Docker bind volume для PostgreSQL data directory.
- Вручную не редактировать.
- Не хранить здесь Parquet, reports или raw datasets.

pgadmin/
- Docker bind volume для pgAdmin.
- Хранит pgAdmin settings/sessions metadata.

parquet/normalized/
- Основной normalized event layer.
- Все события разных форматов приводятся к canonical schema.
- Деление обязательно по branch и role.

parquet/features/
- Feature tables после feature engineering.
- Разделение по feature_group обязательно.
- labels/context columns сохраняются отдельно от X model features.

parquet/model_ready/
- Финальные X/y/sequences/preprocessing/split artifacts.
- TEST artifacts не используются для обучения preprocessing.

DuckDB/
- proposal_analytics.duckdb может хранить persistent views/macros.
- sql/ хранит SQL scripts for views/checks.
- exports/ хранит выгрузки diagnostic queries.

reports/
- ru/en/stage-two: task reports для Codex implementation.
- parser: parsing summaries and error reports.
- normalization: normalized artifact reports.
- quality: missing values, duplicates, schema checks.
- leakage: data leakage check reports.
- schema_mismatch: schema mismatch reports.

logs/stage-two/
- Runtime logs для ingestion, parser routing, normalization, parquet writing, DuckDB checks.

backups/
- PostgreSQL catalog dumps.
- Export metadata snapshots.
- Не хранить большие raw copies без необходимости.

temp_data/
- Временные ingestion summaries.
- Parser batch state.
- Normalization intermediate files.
- Можно очищать только после проверки регистрации artifacts в PostgreSQL.

schemas/
- JSON/YAML schema contracts для normalized/features/model_ready.
- Версии должны соответствовать schema_versions в PostgreSQL.

config/
- parser_registry_seed.json: начальное наполнение parser_registry.
- label_mapping_rules.json: правила label resolver.
- duckdb_views.sql: SQL views поверх Parquet.

4. .ENV
================================================================================

Рекомендуемый .env.example:

PATH_DATA_STORAGE=C:\Users\Public\PythonProjects\storage
PATH_FOLDER_DATASETS=C:\Users\Public\PythonProjects\storages\datasets
PATH_FOLDER_DATASETS_FILTER=C:\Users\Public\PythonProjects\storages\datasets-filter

POSTGRES_DB=proposal_catalog
POSTGRES_USER=proposal_user
POSTGRES_PASSWORD=proposal_password
POSTGRES_PORT=5432
DATABASE_URL=postgresql+psycopg://proposal_user:proposal_password@localhost:5432/proposal_catalog

PGADMIN_PORT=5050
PGADMIN_DEFAULT_EMAIL=admin@example.com
PGADMIN_DEFAULT_PASSWORD=admin

PATH_REPORT=${PATH_DATA_STORAGE}/reports
PATH_TEMP_DATA=${PATH_DATA_STORAGE}/temp_data

Правила:
- .env не коммитить;
- .env.example можно коммитить только с placeholder values;
- production passwords не хранить в Git;
- DATABASE_URL нужен SQLAlchemy/Alembic;
- PATH_DATA_STORAGE должен быть единственным корнем для generated artifacts.

5. DOCKER-COMPOSE
================================================================================

Рекомендуемый docker-compose.yml:

services:
  postgres:
    image: postgres:16
    container_name: proposal-postgres
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    ports:
      - "${POSTGRES_PORT}:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

  pgadmin:
    image: dpage/pgadmin4:8
    container_name: proposal-pgadmin
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    environment:
      PGADMIN_DEFAULT_EMAIL: ${PGADMIN_DEFAULT_EMAIL}
      PGADMIN_DEFAULT_PASSWORD: ${PGADMIN_DEFAULT_PASSWORD}
    ports:
      - "${PGADMIN_PORT}:80"
    volumes:
      - pgadmin_data:/var/lib/pgadmin

volumes:
  postgres_data:
    driver: local
    driver_opts:
      type: none
      o: bind
      device: ${PATH_DATA_STORAGE}/postgres

  pgadmin_data:
    driver: local
    driver_opts:
      type: none
      o: bind
      device: ${PATH_DATA_STORAGE}/pgadmin

6. PATH POLICY
================================================================================

В PostgreSQL хранить:
- raw_absolute_path: допускается для исходных файлов, если они вне PATH_DATA_STORAGE;
- raw_relative_path: путь относительно PATH_FOLDER_DATASETS или PATH_FOLDER_DATASETS_FILTER;
- artifact_relative_path: путь относительно PATH_DATA_STORAGE для generated artifacts;
- artifact_uri: optional, если позже появится object storage.

Для Parquet artifacts использовать относительные пути:
- parquet/normalized/dns/TRAIN/...
- parquet/features/dns_features/TRAIN/...
- parquet/model_ready/tabular/dns/TRAIN/...

Причина:
- переносимость проекта;
- стабильный catalog при переносе storage root;
- меньше риска сломать artifacts при смене машины.

8. ACCEPTANCE CRITERIA
================================================================================

- Все directories создаются без ручного вмешательства.
- Docker PostgreSQL и pgAdmin стартуют через docker compose.
- PostgreSQL healthcheck успешен.
- DATABASE_URL работает для SQLAlchemy.
- Generated artifacts пишутся только в PATH_DATA_STORAGE.
- Raw datasets не изменяются.
- Parquet directories физически разделены по normalized/features/model_ready.
- Reports directories содержат ru|en/stage-two.
- В catalog хранятся относительные artifact paths.
