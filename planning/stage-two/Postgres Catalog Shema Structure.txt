ФИНАЛЬНАЯ POSTGRESQL CATALOG SCHEMA ДЛЯ STAGE TWO
================================================================================

1. НАЗНАЧЕНИЕ POSTGRESQL CATALOG
================================================================================

PostgreSQL используется как управляющий catalog/pipeline-control слой.
Он не используется как хранилище больших normalized events, feature matrix,
sequence windows, full packet payload или BSON streams.

Catalog должен хранить:
- datasets and roles;
- raw dataset files;
- ingestion runs;
- parser registry;
- parser runs;
- schema versions;
- normalized artifacts;
- feature artifacts;
- model-ready artifacts;
- preprocessing artifacts;
- label mapping rules;
- data quality reports;
- traceability across all layers.

15. NULL POLICY
================================================================================

Правило:
Если нужного значения нет в исходном файле датасета, в соответствующую колонку
PostgreSQL/Parquet записывать NULL.

Примеры:
- нет timestamp -> timestamp=NULL, timestamp_type='missing', event_index сохраняется;
- нет label -> label_binary=NULL, label_status='unlabeled', label_source='none';
- нет host.name -> host_name=NULL;
- DNS TXT/domain-list не имеет src_ip -> src_ip=NULL;
- PCAP packet без DNS layer -> qname/query_domain=NULL;
- BSON args с неизвестной структурой -> конкретные колонки NULL, raw_fields_json заполнен.

Не делать:
- не записывать пустую строку вместо NULL;
- не записывать 0 вместо отсутствующего numeric value;
- не считать NULL label как benign;
- не использовать TEST statistics для заполнения NULL.

16. РЕКОМЕНДУЕМЫЙ DDL-ФРАГМЕНТ
================================================================================

Примечание: полный DDL лучше реализовать через Alembic migration на основе SQLAlchemy
models. Ниже - ориентир для constraints.

CREATE TABLE datasets (
    id BIGSERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    slug TEXT NOT NULL,
    branch TEXT NOT NULL CHECK (branch IN ('dns','host','network','hybrid')),
    role TEXT NOT NULL CHECK (role IN ('TRAIN','VALIDATION','TEST','EXPERIMENTS')),
    source_group TEXT,
    description TEXT,
    dataset_version TEXT,
    source_url TEXT,
    license_name TEXT,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    metadata_json JSONB,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uq_datasets_name_branch_role UNIQUE (name, branch, role),
    CONSTRAINT uq_datasets_slug_branch_role UNIQUE (slug, branch, role)
);

CREATE TABLE ingestion_runs (
    id BIGSERIAL PRIMARY KEY,
    run_uid UUID NOT NULL UNIQUE,
    root_path TEXT NOT NULL,
    root_path_kind TEXT NOT NULL,
    branch TEXT CHECK (branch IS NULL OR branch IN ('dns','host','network','hybrid')),
    role TEXT CHECK (role IS NULL OR role IN ('TRAIN','VALIDATION','TEST','EXPERIMENTS')),
    started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    finished_at TIMESTAMPTZ,
    status TEXT NOT NULL DEFAULT 'RUNNING' CHECK (status IN ('RUNNING','SUCCESS','PARTIAL_SUCCESS','FAILED','SKIPPED')),
    files_seen INTEGER NOT NULL DEFAULT 0,
    files_new INTEGER NOT NULL DEFAULT 0,
    files_existing INTEGER NOT NULL DEFAULT 0,
    files_changed INTEGER NOT NULL DEFAULT 0,
    files_failed INTEGER NOT NULL DEFAULT 0,
    error_message TEXT,
    report_path TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

Остальные таблицы реализовать в Alembic migration по списку колонок выше.

17. ACCEPTANCE CRITERIA
================================================================================

- Все таблицы созданы через Alembic.
- Все role/branch/status values ограничены CHECK constraints.
- dataset_files поддерживает idempotent upsert.
- parser_runs связаны с dataset_files.
- normalized_artifacts связаны с parser_runs and dataset_files.
- feature_artifacts связаны с normalized_artifacts where applicable.
- model_ready_artifacts связаны с feature/preprocessing artifacts.
- preprocessing_artifacts имеют fitted_on_role='TRAIN'.
- label_mapping_rules позволяют объяснить label_source/status.
- data_quality_reports фиксируют quality/leakage/schema checks.
- Traceability chain проходит от model_ready до raw file.
- Большие events/features не хранятся в PostgreSQL.
