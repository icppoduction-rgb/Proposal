ДЕКОМПОЗИЦИЯ ЗАДАЧИ ДЛЯ CODEX
Расширение Stage Two parser layer для полного покрытия форматов датасетов

Проект:
Proposal - Behaviour-driven hybrid learning for data exfiltration detection

Источник декомпозиции:
/mnt/data/codex_task_stage_two_full_parser_implementation.txt

Цель этого документа:
Разбить одну большую задачу по реализации полного Stage Two parser layer на последовательные малые задачи для Codex так, чтобы каждая задача имела четкий вход, выход, критерии приемки и связь со следующей задачей. Логика реализации не должна обрываться: каждая задача либо готовит foundation для следующих задач, либо подключает уже реализованные части к текущему pipeline.

0.3. Архитектурная цепочка, которую нельзя ломать

RAW DATASETS
  -> CATALOG INGESTION
  -> POSTGRESQL CATALOG
  -> PARSER REGISTRY / RESOLVER
  -> PARSER RUN
  -> NORMALIZED EVENTS
  -> PARQUET NORMALIZED LAYER
  -> NORMALIZED_ARTIFACTS REGISTRATION
  -> DUCKDB QUALITY / LEAKAGE CHECKS
  -> TRACEABILITY

0.4. Жесткие инварианты

- Raw datasets не изменять, не исправлять, не перемещать, не перезаписывать.
- PostgreSQL не использовать как storage для больших normalized events, feature matrix, packet payload, BSON streams или raw logs.
- Большие outputs писать в Parquet через существующий Parquet writer.
- Сохранять traceability raw file -> parser_run -> normalized_artifact.
- TRAIN, VALIDATION и TEST не смешивать.
- TEST не использовать для filename-based label heuristic, preprocessing fit, model training или threshold tuning.
- Labels не должны попадать в X/features как input columns.
- Missing/unknown значения писать как None/NULL, а не synthetic placeholders.
- Нестандартные поля сохранять в raw_fields_json, features_json или metadata_json.
- Существующие команды normalize-dns и normalize-host должны продолжить работать.
- Новый функционал должен быть backward-compatible.

================================================================================
1. КАК ИСПОЛЬЗОВАТЬ ЭТУ ДЕКОМПОЗИЦИЮ
================================================================================

1.1. Правило выполнения

Codex должен выполнять задачи строго по порядку. Нельзя сразу начинать с реализации всех parser classes, пока не закрыты:
- baseline inspection;
- input reader;
- source_format inference;
- parser registry consistency;
- parser coverage diagnostics.

1.2. Коммитная стратегия

Рекомендуется один commit на одну задачу или на небольшой логически цельный блок задач. В конце каждой задачи Codex должен дать:
- список измененных файлов;
- краткое описание изменений;
- команды проверки;
- результат проверок;
- что является входом для следующей задачи.

1.3. Минимальная проверка после каждой задачи

После каждой задачи, которая меняет Python-код:

python -m compileall manage.py config.py scripts
git diff --check

Если задача меняет DB/catalog behavior:

python -m scripts.db.smoke_check
python -m alembic -c scripts/db/migrations/alembic.ini current

Если задача меняет parser registry/resolver:

python manage.py stage-two seed-parser-registry
python manage.py stage-two parser-coverage

1.4. Что не входит в эту цепочку задач

Не реализовывать здесь:
- финальное обучение ML/DL моделей;
- hyperparameter tuning;
- SHAP reports;
- финальную evaluation-таблицу модели;
- production feature generation для всех normalized artifacts, кроме минимальных smoke-заглушек если они уже нужны existing checks;
- production model-ready build pipeline;
- объединение всех данных в один CSV;
- хранение all normalized events в PostgreSQL;
- удаление или исправление raw datasets.

Task 06. Добавить safe base64 и compression handling
--------------------------------------------------------------------------------

Цель:
Поддержать whole-file, line-level и JSON field-level base64 там, где это безопасно, а также common compression.

Файлы:

Что реализовать:

   - bz2

   - binary
2. Base64 detection:
   - whole-file base64;
   - line-level base64;

   - valid base64 alphabet;

   - base64_detected;
   - decode_strategy;
   - compression_hint;
   - decode_error.

Ограничения:
- Не выполнять decoded content.
- Не распаковывать archive paths на filesystem.
- Не хранить full decoded payload in metadata_json.

Критерии приемки:
- Smokes: base64 CSV, base64 JSON-lines, base64 raw log line.
- Smokes: gzip text, bz2 text, xz text if standard libs available.
- Oversized/invalid base64 gives warning, not crash.
- compileall проходит.
